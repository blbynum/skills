# Note or doc?

The same table, word for word, lives in the note-author skill and in the
docs skill. Apply it before a write. When the answer points at the other skill,
hand the work there and say so.

Decide by the reader and the use, not by length or polish. A rough text
that a reader acts on is a doc; a careful text only its author will reread
is a note.

| Ask | Note | Doc |
|---|---|---|
| Who reads it? | The author, later | Someone else, or the author as a member of a team |
| What is it for? | A fact to look up again | Something a reader acts on, or a record of a decision |
| What shape has it? | One idea, standalone, linked to other notes | One kind: a plan, a design, a PRD, a report, a runbook, a guide, a reference |
| What does it carry? | A confidence and an updated date | A home, an owner, a status |
| Where does it live? | The notes store | The document platform, or the repository when it ships with code |

Three rules:

1. **Scratch is neither.** Session progress, what was tried, what to do
   next in this session: keep it in the session. Do not write it as a note
   and do not file it as a doc.
2. **One piece of work can yield both.** A research write-up is a doc; the
   facts it settled are notes. Write the doc, then the notes. Never write
   one as the other.
3. **A note becomes a doc by composition, not by moving.** When a reader
   appears, write the doc from the notes. The notes stay.

When in doubt: if a second person would open it to do something, it is a
doc.
